# Text & i18n Reference

Load only for text/localization operations.

## Stable identity

Address text as:

`semantic key path + locale`

Do not use translated sentence matching when a stable key exists.

Supported patterns include:

1. centralized named objects, e.g. `content.ts -> PHOTOS_CONTENT.subtitle`;
2. one typed locale file per language with identical semantic keys, e.g. `locales/en.ts`, `locales/pl.ts`, key `home.hero.title`.

The second pattern is preferred for mature multilingual sites.

## Locale resolution

Priority:

1. locale explicitly named in current request;
2. active session website-locale context;
3. uniquely matching configured source;
4. configured default locale;
5. ask if still ambiguous.

Never infer website locale from the language used to speak with the assistant.

## Change classes

**Wording/style:** active locale only by default.

**Factual/semantic:** keep configured locale variants consistent unless the user explicitly limits scope.

For multi-locale factual changes verify:

- same semantic key exists;
- numbers/units match;
- names/entities match;
- links/emails/placeholders match;
- no locale retains the stale old fact.

## Repeated blocks

For arrays/cards/services, identify logical items by stable `id`, `slug`, object/category key, or unique identity before ordinal position.

Across locales, match by stable identity, never translated title text.

## Fit guard

Do not solve longer translations by changing CSS, fonts, spacing, width, breakpoints, manual `<br>`, or hidden omissions.

If correct copy cannot fit within authorized design, stop and request separate design authorization.

For RTL locales, use existing RTL support only. Do not introduce direction/layout code under a content-only profile.
